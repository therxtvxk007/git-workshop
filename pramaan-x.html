Architecture brief August 2026 Configuration v1 — frozen

PRAMAAN-X

A multimodal event-forecasting platform with calibrated risk guarantees.

The criticism should change the presentation, not push you into replacing every mature method with a fashionable tool. C++ is not obsolete — PyTorch, vLLM and CUDA all depend on it heavily. But the visible project must be Python/PyTorch-first, with C++ confined to profiled, performance-critical components.

The system should read as a 2026 research platform, not a C++ coursework application.

01 — Position

Where the novelty actually lives

No single component here is the contribution. The contribution is what happens between them.

Composition
Module interaction
Extraction, retrieval, graph and hazard signals feed one another rather than running as a pipeline of disconnected demos.
Objective
Constraint-based optimisation
Specificity is maximised subject to a certified bound on missed events — not tuned by hand until a metric looks acceptable.
Method
Leakage-proof evaluation
Immutable historical cutoffs and content hashes, so no evidence dated after the forecast can enter the forecast.
Coverage
Open-set completeness
Events that fit no known class are preserved as candidates rather than discarded by a closed-set classifier.
Evidence
Multimodal temporal retrieval
Text, images, screenshots and video ranked jointly, with recency, long-run pattern and provenance scored explicitly.
Guarantee
Prospective verification
Hashed forecasts committed before outcomes are known, so results cannot be reconstructed after the fact.
02 — Architecture

End-to-end flow

Seven stages, each one addressing a named failure mode. Evidence enters immutably at the left and leaves as a tiered, auditable ledger entry at the right.

STAGE 1Immutable multimodal event streamText, image, video and screenshot sources with fixed publication cutoffs.
STAGE 2Zero-shot joint extractionEntities, relations and event tuples in a single encoder pass, schema-constrained.
STAGE 3Hybrid retrieval + temporal graphFour-stage cascade over a queryable graph of event provenance and paths.
STAGE 4High-recall hypothesis unionFour independent generators unioned, then diversity-selected.
STAGE 5Hazard ensemble + sequential evidenceDiscrete-time risk over future windows, accumulated across weak signals.
STAGE 6Conformal risk controlSet size grown until the false-negative bound is certified.
STAGE 7Alert / Watch / Monitor ledgerHashed, timestamped, analyst-facing output.

04 — Temporal retrieval

Beyond ITHI: adding LANTERN and MTRM

The earlier design used ITHI's three historical-information types. Two 2026 results should now be folded in.

LANTERN — long window against short window

LANTERN separates long-window strength (stable interaction patterns) from short-window novelty (sudden change), then uses Pareto-greedy selection to build a compact evidence set and adds a structure-aware analogy term. It reports gains over the previous training-free baseline on ICEWS14, ICEWS05-15, ICEWS18 and GDELT.

R(d) = w₁Rsemantic + w₂Rrecency + w₃Rlong-pattern + w₄Rnovel-shift + w₅Rsource + w₆Ranalogy The retrieval score gains two terms the earlier design lacked: a long-run pattern term and a novelty-shift term, so a stable relationship and a sudden break are scored separately instead of being averaged into one recency weight.

MTRM — many granularities, not one

MTRM combines signals across several temporal granularities rather than choosing between global cycles and adjacent events. Implement features at each horizon and let the hazard model learn which one matters for each event type.

05 — Retrieval cascade

Four stages, then temporal and provenance scoring

Do not present "I used a vector database and RAG." That is now ordinary. The cascade is what makes the retrieval defensible.

  1. Sparse retrieval
    BM25 for names, places and precise terminology — where dense embeddings reliably lose exact tokens.
  2. Dense retrieval
    Multilingual semantic embeddings for paraphrase and cross-language recall.
  3. Late interaction
    Token- and image-patch-level matching, preserving evidence that a single pooled vector destroys.
  4. Cross-encoder / listwise reranking
    Expensive, high-precision ranking applied only to the surviving candidates.
S(d, q, t) = αSBM25 + βSdense + γSlate + δSreranker + ηStemporal + ρSprovenance This attacks retrieval error directly — the bottleneck identified by AutoCast++ and the event-forecasting work that followed it.
06 — Extraction

Neuro-symbolic, not brute force

Do not ask a 27B model to repeatedly scan every document. Use a cheap high-recall extractor, and spend the large model only where it earns its cost.

  1. GLiNER-Relex for joint NER and relation extraction
    High recall in a single encoder pass over the full corpus.
  2. A small classifier for event type and relevance
    Filters the stream before any large model is invoked.
  3. The main LLM only for ambiguity and verification
    Structured verification of hard cases, not bulk annotation.
  4. Consensus before graph insertion
    Agreement between extractors gates high-confidence writes.
  5. Conflicts retained with uncertainty
    Disagreement is recorded, never arbitrarily resolved in favour of one extractor.

07 — Candidate generation

Four independent branches, then a union

Recall first. Each branch fails differently, which is the entire reason for running four.

Branch 1
SCATTER-style LLM
Diverse plausible hypotheses, including ones no structural model would propose.
Branch 2
Temporal knowledge graph
Structural continuations of established event chains.
Branch 3
Classical hazard
High-base-rate and temporal-risk events that statistics catch and language models miss.
Branch 4
Open-set anomaly
Suspicious patterns that fit no known class and would otherwise be dropped.

Take the union, then apply a learned diversity selector so twenty paraphrases of the same event cannot occupy the whole prediction set.

Do not fine-tune the main model immediately. Start with QLoRA supervised adaptation and add GRPO only once you have enough validated outcome and reward data — poorly designed reinforcement learning will optimise the evaluator's quirks rather than forecasting quality.

08 — Risk control

Conformal risk control, not ordinary conformal prediction

This is the strongest update in the design. Define the loss as the missed-event proportion and control it directly.

LFN(X, Y, λ) = 1 − |Y ∩ Cλ(X)||Y| Grow the candidate set until the calibrated upper bound on false-negative risk meets the target. The official Conformal Risk Control implementation already expresses this class of multi-label false-negative loss.
maxθ,λ Specificity subject to   U1−δ(FNRθ,λ) ≤ ε where U1−δ is an upper confidence bound on the false-negative rate. A 2025 NeurIPS result demonstrated exactly this end-to-end optimisation of specificity under a controlled false-negative rate. This is what formalises the C-DAC requirement — not a promise about recall, a certificate.
09 — Keep / drop

What stays classical, and what must not be the visible core

"Cutting edge" means using the strongest method for each subproblem — not replacing a superior statistical method with a transformer for appearance.

Keep — inside the ensemble

Not embarrassing legacy choices

  • Logistic regression
  • LightGBM
  • BM25
  • CUSUM
  • Survival analysis
  • Isotonic calibration

The 2026 conflict-forecasting result — logistic regression beating large LLMs — is precisely why mature statistical tools remain necessary. TF-IDF, BM25 and logistic regression belong in the baseline and the ensemble. They simply must not be the entire system.

Drop — as the headline contribution

Never the project's visible core

  • C++ console application
  • Vanilla LSTM
  • Standalone BERT classifier
  • word2vec-only similarity
  • Plain TF-IDF classification
  • Static knowledge graph
  • Cosine-only vector RAG
  • One prompt to ChatGPT
  • LangChain wrapper with no original algorithm
  • Random train/test split
  • Accuracy as the principal metric
  • SMOTE as the main rare-event solution
  • Post-event web retrieval
  • Manually selected attack clues
  • UI-first development
10 — The answer

If they ridicule C++ again

One sentence. It settles the language question and demonstrates that you understand both research and systems engineering.

Say this
The research stack is Python 3.14 and PyTorch 2.13, with Qwen3.8 served through vLLM/SGLang, hybrid late-interaction retrieval, temporal graph forecasting and conformal risk control. C++ is limited to the CUDA and inference kernels underneath the Python layer.
